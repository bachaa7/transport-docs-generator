# Transport Docs Generator

**Веб-сервис, который по одной форме собирает пакет документов на перевозку груза вместо ручного копирования в Word и Excel.**

Python · FastAPI · Pydantic · docxtpl · openpyxl · PyInstaller · n8n (опционально)

---

## Задача

Оптовая компания закупает металлопрокат у заводов в России и возит его фурами в Беларусь.
На **каждый рейс** менеджер готовил 2–4 документа:

| Документ | Формат | Когда нужен |
|---|---|---|
| Заявка на транспортную перевозку | Word | всегда |
| Доверенность на водителя (форма М-2) | Word | почти всегда |
| Гарантийное письмо | Word | если поставщик требует |
| «Заказ на поставку» — бланк поставщика | Excel с макросами | если поставщик работает по своему бланку |

Всё заполнялось вручную копированием из переписки с перевозчиком: ФИО водителя, паспорт,
номера машины и прицепа, адреса складов, контакты. Отсюда ошибки в паспортных данных,
перепутанные склады, разные номера одной доверенности в разных документах.

## Решение

Менеджер открывает веб-форму, выбирает поставщика и склад из справочников,
вставляет сообщение перевозчика как есть — и получает готовый пакет:

1. **Разбор сообщения перевозчика.** Текст вида
   `Авто: … Прицеп: … Водитель: … Паспорт: … Тел.: …` раскладывается по полям формы
   (`parser.py`), менеджер только проверяет.
2. **Состав пакета определяется справочником, а не кодом.** У каждого поставщика
   в YAML указан тип складского документа (`znp` / `garant` / `net`). Новый поставщик
   добавляется без программиста.
3. **Заполнение чужого Excel-бланка без меток.** Бланк поставщика приходит новый
   на каждый заказ, и число строк продукции в нём «плавает». Поэтому ячейка ищется
   не по адресу, а по **подписи в колонке A + жёлтой заливке** поля ввода.
   Правила лежат в `ЗНП_карта_полей.yaml`; если поставщик поменяет бланк,
   правится YAML, а не код. Макросы бланка при этом сохраняются.
4. **Подпись и печать** накладываются плавающими картинками поверх линий подписи
   (по галочке в форме, с подтверждением).
5. **Сквозная нумерация**: исходящие номера `ДДММ/N` и счётчик доверенностей
   ведутся сервисом, номер одной доверенности одинаковый во всех документах пакета.
6. **Количество прописью** для доверенности считается само (`num2words`).
7. **Результат**: папка рейса `ПОСТАВЩИК_Исх№_дата-время`, скачивание файлов
   по одному или ZIP-архивом; опционально — PDF через LibreOffice.

## Что сделал я

- Разобрал реальные документы компании (~20 заявок, доверенности, бланки поставщиков),
  выделил общую структуру и сделал из них Jinja-шаблоны Word.
- Спроектировал справочники (поставщики, склады погрузки, точки выгрузки, перевозчики)
  в YAML так, чтобы их можно было заменить выгрузкой из 1С.
- Написал FastAPI-сервис, модели запроса на Pydantic с мягкой валидацией
  (предупреждения вместо отказа там, где менеджер может знать лучше).
- Сделал веб-форму без фреймворков: зависимые списки, условные блоки по поставщику,
  загрузку файлов, подсказки по составу пакета.
- Закрыл обход путей (path traversal) при скачивании и при сохранении загруженных файлов.
- Собрал `.exe` через PyInstaller, чтобы менеджеры запускали сервис двойным щелчком
  без установки Python; подготовил инструкцию для Linux-сервера и интеграцию с n8n.

## Как это выглядит

```
Форма (/form)  ──►  POST /generate  ──►  output/ALFA_1606_2_2026-06-16_101500/
                                            ├─ zayavka_1606_2.docx
                                            └─ znp_1606_2.xlsx
```

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate            # Linux: source .venv/bin/activate
pip install -r requirements.txt
python config.py                  # проверка: все шаблоны и справочники на месте
python test_trips.py              # сквозной тест: два рейса + ошибочный запрос
python main.py                    # откроется http://127.0.0.1:8077/form
```

Подпись и печать в репозиторий не входят. Чтобы проверить наложение, положите любые PNG
в `assets_private/` (`podpis_ruk.png`, `podpis_buh.png`, `pechat.png`).

- Linux-сервер: [DEPLOY_LINUX.md](DEPLOY_LINUX.md)
- Сборка `.exe` для Windows: [СБОРКА_EXE.md](СБОРКА_EXE.md)

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | проверка работы, список поставщиков |
| GET | `/form` | веб-форма |
| GET | `/spravochniki` | справочники для формы |
| POST | `/parse_voditel` | разбор текста перевозчика в поля водителя |
| GET | `/next_nomer` | следующие исходящие номера |
| POST | `/upload_znp`, `/upload_spec` | загрузка бланка заказа / спецификации |
| POST | `/generate` | сформировать пакет документов |
| GET | `/files/{session}/{name}`, `/zip/{session}` | скачать файл / весь пакет |

Swagger: `http://127.0.0.1:8077/docs`.

## Структура

```
main.py          FastAPI: эндпоинты, состав пакета, наложение подписей
schemas.py       модели запроса (Pydantic)
context.py       сборка данных для шаблонов, значения по умолчанию
generators.py    Word (docxtpl), Excel (openpyxl, поиск ячеек по карте полей), PDF
parser.py        разбор сообщения перевозчика
validators.py    мягкая валидация → предупреждения
numbering.py     исходящие номера и счётчик доверенностей
propis.py        количество прописью
references.py    загрузка справочников
config.py        пути и константы
form.html        веб-форма (HTML + JS)
test_trips.py    сквозной тест
input_dir/       демо-шаблоны, бланк ЗНП, справочники, карта полей
n8n/             workflow для n8n (необязательно)
```
